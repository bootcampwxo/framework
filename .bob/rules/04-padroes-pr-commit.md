# Padrões de PR e Commit (aplica-se a todos os modos)

## Formato da mensagem de commit
Use commits convencionais sempre que possível:
- feat: ...
- fix: ...
- test: ...
- docs: ...
- chore: ...
- refactor: ... (somente quando justificado pela história)

## Descrição do PR (seções obrigatórias)
- O que mudou
- Por quê (link para história/issue)
- Como verificar (comandos + passos)
- Evidência de teste (o que rodou, resultados)
- Risco/impacto + plano de rollback
- Notas de segurança (se aplicável)
- Documentação atualizada (onde)

## Disciplina de escopo
- Um PR = uma intenção.
- Evite misturar mudanças não relacionadas.
